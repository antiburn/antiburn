# Claude Code installation

Claude Code is the first rollout, with an unreleased 0.2.5 candidate. The catalog on `main` points to an earlier candidate snapshot; validate this revision against its exact artifact SHA in a fresh host profile. This guide covers Terminal and the Code tab in Claude Desktop. Use the [plugin page](../../plugins/README.md#install) for marketplace installation, usage, updates and removal, and the [distribution guide](distribution.md) for the permanent source and immutable artifact pin.

Codex, Cursor, OpenCode and Pi are unpublished adapters. Their contributor procedures live in [Unpublished adapters — contributor testing only](development-adapters.md); they are not public installation routes.

## Before installing

- Choose one source and scope. Preserve unrelated installations and settings.
- For acceptance testing, use temporary host profiles and disposable projects.
- Confirm that the Claude Code mod runtime is enabled. The plugin does not require the antiburn desktop app, CLI or a separate antiburn account.
- Verify the artifact version and source, automatic usage display, help, refresh, reload and removal. A file copy alone does not establish native operation.

## Load from a source checkout

Use the [plugin guide](../../plugins/README.md) for the 0.2.5 candidate.
The 0.2.5 candidate fixes Desktop meter width and composition with other mods.
Quota behavior is unchanged. Verify an update from 0.2.4 and fresh installation
before promotion.
One-session loading uses:

```sh
claude --plugin-dir ./plugins/antiburn
```

This is the same self-contained artifact generated by the Claude builder; the
cross-agent assembler delegates to that builder rather than producing a second
public Claude runtime. Public usage/help/refresh commands never require Node, an antiburn
executable or the desktop app. CLI discovery belongs only to development builds.

## Claude local lifecycle validation

Use disposable profiles and projects. Validate the public and development
artifacts independently, then together. Preserve unrelated installations,
settings and credentials.

1. Check fresh installation, enable/disable, retained-data uninstall, reinstall
   and removal in the supported user, project and local scopes.
2. Compare installed public files with the immutable artifact pin. Local file
   transport does not establish hosted delivery; verify the permanent marketplace
   route on `main`, as described in [distribution](distribution.md).
3. Check separate public `antiburn` and local `antiburn-dev` records, commands
   and state. Co-loading must produce only one usage strip.
4. Run quota and development regression suites, including clear/resume, reload,
   pending requests, stale events, check actions and teardown.
5. Verify `/antiburn help`, `/antiburn` and `/antiburn refresh` in native Terminal
   and Desktop Code sessions. Record host versions and artifact hashes; keep
   synthetic fixtures labeled. Public commands need an enabled mod runtime.

Generate both builds and run the reusable local rehearsal:

```sh
node scripts/assemble-claude-mod.mjs
node scripts/assemble-claude-mod.mjs --dev
node scripts/check-claude-mod-lifecycle.mjs
```

The rehearsal creates temporary profiles, projects and signed disposable Git
fixtures. It must not modify production profiles, shared catalogs, authentication
files or unrelated user skills. Keep the `antiburn-local-dev` marketplace and
`antiburn-dev` build local; exclude them from the public catalog. See the
[development guide](../../plugins/antiburn-live/README.md) for debug controls.

## Claude native test harness

Run the exact-artifact and full development suites from the unified plugin guide.
They load the actual composition entry, quota code and development checks. Mocked
host calls establish behavioral regression coverage; record native Terminal and
Desktop acceptance separately. Do not include tests or host-generated SDK types
in distributed bytes.
